# daffodil 0.7.2 is on PyPI

Ray asked for this release so AuditEngine can use it. Pin `daffodil==0.7.2` in the Lambdas.

The release has tag v0.7.2 on e66b189, and its GitHub Release is "Version 0.7.2".
The Full deploy run passed every job: https://github.com/raylutz/daffodil/actions/runs/38185125280

`main` now reads 0.7.3.dev0. Run `uv sync` after pulling daffodil, so the editable install shows it.

## Please act on

- Install `daffodil[pyjson5]` in the Lambdas, or add `pyjson5` to the requirements. Daffodil then reads
  the text of list and dict cells, such as indirect columns in CSV files, with pyjson5. An
  indirect-column load of 10,000 rows took 0.211 s instead of 1.723 s. `rays_requirements.txt` lists
  `json5==0.9.5`. That is a different package, pure Python, and daffodil does not use it. Without
  pyjson5, daffodil works as before.
- `reduce()` with `by='row'` gives each row as a KeyedList, not a dict. `sum_kl()` and
  `count_values_kl()` are the standard reducers, and `reduce()` uses them in place of `sum_da()` and
  `count_values_da()`. A function of AuditEngine's own that is passed to `reduce()` and needs a real
  dict should call `dict(row)`. Writing to the row changes the table.
- `count_values_da()` and `count_values_kl()` raise TypeError on a list cell, naming the column. Leave
  such a column out with `cols`.
- `iter_dict()`, `iter_klist()` and `iter_list()`, and so `for row in daf`, return generators. Two uses
  differ. An iterator that was used up gives nothing when looped again. A loop goes on through the rows
  it started with when a sort puts a new list of rows in place. Code that keeps an iterator to loop over
  twice should call the method again.

## Faster, with the same results

- `import daffodil` no longer needs pandas or numpy, and takes 0.09 s instead of 1.08 s. That shortens
  a Lambda cold start.
- One-cell reads and writes by key: `daf[key, col] += x` went from 6.8 to 0.86 us.
- Row loops on 100,000 rows: dicts 0.093 to 0.049 s, KeyedLists 0.110 to 0.053 s, lists 0.050 to 0.005 s.
- `groupby_cols()` with `cols`, at 43,000 groups: 0.747 to 0.602 s.

## New

- `Daf.check_schema()` checks each cell against the dtypes, and the required columns of an attached
  schema. It raises ValueError naming each bad row. It runs only when called. A sum skips a value it
  cannot add with no error, so call it after a load when a bad number would matter.

The full list is in CHANGELOG.md, under 0.7.2.
