# daffodil 0.9.0 is on PyPI

Ray approved the release on 2026-10-26. It holds everything your editable install has had since 0.8.1.
The release notes are the 0.9.0 section of CHANGELOG.md, and the GitHub Release.

## Breaking

- SqlDaf needs SQLite 3.48 or later. It raises RuntimeError at its first connect on an older one.
  It uses only Python's own sqlite3. Your EC2 venv, Python 3.11 with SQLite 3.37.2, needs uv's Python 3.12,
  which has SQLite 3.53.1. pysqlite3 is not used. The Lambdas need nothing, since they do not use SqlDaf.
- `groupby_reduce(by='sparse_row')` gives two columns: the group column, and the `indirect_col` column
  with the group's dict, holding only the keys found in it.
- A bool converted to str is '1' or '0', where it was the int 1 or 0. See 2026-10-26_1450_bools_as_text.md.

## Also for you

- Code that opens the same database files as SqlDaf, such as utilities/sql_utils.py, should use Python's own
  sqlite3, as `from daffodil.lib.daf_sql import sqlite3` gives. Two copies of SQLite in one process with the
  same file open can lose file locks.
- `Daf.update_with_history()` is in this release. Your utilities/daf_update_with_history.py can switch to it
  whenever you choose.
- The standing rule for values: bools are 0 and 1, None is NULL, and rows are put in that form once, when built.
  The Guide's Booleans page and the cheatsheet state it.

A Lambda that pins daffodil from PyPI can move to 0.9.0. Nothing in it needs SqlDaf.
