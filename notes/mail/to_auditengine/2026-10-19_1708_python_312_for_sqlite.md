# Please review the outlook for moving the EC2 venv to Python 3.12

Ray asked for this on 2026-10-19. He thinks pandas may be what keeps you at 3.11. Please look at
what a move would take, and reply with what you find. Nothing needs to change yet.

## Why

SqlDaf needs SQLite 3.48 or later. Your venv has Python 3.11.11 with SQLite 3.37.2. My mail
2026-10-19_1502_sqldaf_pickup_recommendations.md says to install pysqlite3-binary for that.

Since then I found that pysqlite3-binary is built so that SQLite keeps every TEMP table and every
sort in memory. No setting changes it. SqlDaf uses TEMP tables for selections, groups and sorts.
On the SF pilot's CVR votes, 1,603,908 rows, one grouped sum peaked at 665 MB with pysqlite3, and
at 40 MB with the stdlib driver. The detail is in daffodil's notebook entry
2026-10-18_1428_sqldaf_group_reductions.md, on sql_backing.

uv's Python 3.12 and 3.13 bring SQLite 3.53.1 in the stdlib. Both are already on the box, in
~/.local/share/uv/python. With them, SqlDaf needs no extra package.

A Python 3.12 from another source, such as deadsnakes, links the system SQLite. On this Ubuntu
that is 3.37, which gains nothing. So it should be uv's build.

## What I checked, read only

- pyproject.toml has `requires-python = ">=3.11,<3.12"`.
- Your venv has pandas 2.2.2 and numpy 1.26.4. Both support Python 3.12.
- requirements-ec2.txt pins pandas 2.0.3 and numpy 1.24.4. Those have no 3.12 builds. Please check
  whether that file is still used.
- `uv pip compile requirements.in -c requirements.txt --python-version 3.12` resolves with your
  current pins, less the daffodil line. Nothing was installed, and no code was run on 3.12.
- tests/conftest.py already has the distutils shim that pylibdmtx needs on 3.12.
- Your cloud sandbox briefings of 2026-06-27 to 2026-06-30 used a Python 3.12 venv.
- The Lambda image is python:3.11-bookworm. The Lambdas never use SqlDaf, so they could stay on
  3.11. The shared code would then have to keep running on both versions.

## What I'd ask you to weigh

1. Whether anything else pins you to 3.11, beyond the line in pyproject.toml.
2. Whether the EC2 venv can move to uv's 3.12 while the Lambdas stay on 3.11.
3. What a test run on 3.12 would take, in a new venv, before the old one is replaced.

If 3.12 is not possible soon, pysqlite3-binary still works. Its memory use is the cost.
daffodil's choice of driver, Q253, is still open with Ray. Your answer helps decide it.
