## The example

    SqlDaf.db_path = '<the working file of the stage>'
    bia_sdaf  = SqlDaf.from_db('biacvr_bif/biacvr_bif.sdaf.db', 'biacvr_bif')
    blt_sdaf  = SqlDaf.from_db('blt_bif/blt_bif.sdaf.db', 'blt_bif')
    full_sdaf = bia_sdaf.join(blt_sdaf, how='left')
    full_sdaf.save('full_bif', db_path='full_bif/full_bif.sdaf.db')

    # ballots with no blt row, to raise on
    missing_sdaf = bia_sdaf.select_records_daf(blt_sdaf, inverse=True, silent_error=True)

A cell with no match is Python NULL, as is a stored NULL. So find the unmatched ballots by key, as above.

## What it does

-  copies the table into the working file, in its row order.
  The keyfield and dtypes come from the table's own daf_tables row. No other table, and no other row of
  daf_tables, is copied. table_sources stays in its file.
- The source is attached read-only, as a URI with mode=ro, for the one statement that copies it.
  SQLite refuses any write to it. It is detached after, even on an error.
-  writes a table into its own file, which is made if needed.
  A TEMP table, such as a join, is moved there. A permanent table is copied. The SqlDaf then refers to it there.
- Names are quoted, so cvr_votes!final works.
- Both raise ValueError inside an open transaction. SQLite cannot detach a file used in one.
- A table already in the working file under that name raises ValueError. Use new_name, or delete it first.
- SqlDaf's connections now allow URI filenames, for the read-only attach. A plain path opens as before.
