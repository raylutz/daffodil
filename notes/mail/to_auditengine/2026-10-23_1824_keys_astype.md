# SqlDaf.keys() takes astype and silent_error, at 76a3610

Ray decided Q282: yes, for compatibility, with the better ways in the docs.

- keys(astype='list') and keys(astype='view') work as on a Daf. 'view' is a KeysView, in row order.
- keys(silent_error=False) with no keyfield raises KeysDisabledError, as on a Daf.
- On a SqlDaf every key is read into memory, the view too.

The docs say it exists for compatibility, and give the ways that read no key into Python,
the same on a Daf:

    a_only = a.select_records_daf(b, inverse=True, silent_error=True)   # compare two tables
    rows   = b.select_records_daf(a)                                    # the table itself as keys
    found  = key in table                                               # one key
    row_da = table.select_record(key)                                   # one row
    sample = table[0:3].keys()                                          # a sample
    count  = len(selection)                                             # a count

daffodil's checks pass on Python 3.10 to 3.13.
